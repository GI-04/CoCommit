## Why
The desktop app still uses the placeholder logo from day one (`src-tauri/app-icon.png`, see `src-tauri/icons/README.md`). It shows in the taskbar/Dock, the installer, the Start menu and the window corner. The team now has a real logo mark from Figma (`public/logo-mark.svg`, added by Trin in `86129b1`), so the app should use it.

## Approach
**After the 11:30 demo.** Work happens on a branch (`kin/app-icons`); nothing reaches `main` before then.
1. Make `src-tauri/app-icon.svg`: the CoCommit mark from `public/logo-mark.svg` in white, centred on a black rounded square (matches the dark Figma look; Kin picked this from a preview, option B), with some padding so it reads at 16 px. Square, with a transparent background outside the rounded corners.
2. Regenerate every size with the Tauri tool we already have (no new packages): `npx tauri icon src-tauri/app-icon.svg -o src-tauri/icons` (the tool takes SVG directly). Remove the `android/` and `ios/` folders it creates (phone is out of scope); they are new, generated files.
3. Keep `src-tauri/app-icon.png` as a 1024 px export of the same icon, so `BUILDING.md`'s steps still work; update `BUILDING.md` and `icons/README.md` to say the source is now `app-icon.svg`.
4. Rebuild the installers on GitHub Actions (macOS + Windows) and replace `public/downloads/` as in PR #38.
5. One PR into `main` with the icons + installers.

Not in this plan (UI area, Trin's call): the website's own favicon and the empty `icons` list in `public/manifest.webmanifest`. The same `app-icon` files could serve them later.

## Files touched

## Risks / needs OK
- **Pattadon's OK** (non-trivial, touches the installers).
- **The look:** Kin picked a white mark on a black rounded square (option B of a blue/black preview). Say if you'd rather have another colour.
- Windows caches icons: an already-installed app may keep the old icon until it's reinstalled or Explorer restarts. Cosmetic only.
- Merging deploys (new installers); do it after 11:30.
