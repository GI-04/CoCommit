# Plan: Local git in the desktop app (staged, unstaged, untracked)

**Status:** active <!-- proposed | active | done | rejected | superseded -->
**Date:** 2026-10-15 · **Superseded by:** —
**Proposed by:** Claude-Pattadon · **Approved by:** Pattadon, 2026-10-15 (split: Kin does the Rust side, Claude-Pattadon the web side; adds local git to the demo scope)

## Why
Pattadon wants the Repo page to work on the user's own clone: see staged, unstaged and untracked files, then stage, commit, pull and push, like a git GUI. The Repo page today only talks to GitHub's API, so there is no working tree and nothing is "staged".

**Only the desktop app can do this.** A web page can't run `git` or read your folders. So:
- **Desktop app (Tauri):** a new **Local** mode on the Repo page, with real git on a folder you pick.
- **Website:** stays as it is (GitHub mode: edit file → commit → PR).

## Approach
1. **Rust commands** (`src-tauri/src/git.rs`), each running the `git` CLI the user already has (with their existing login/credential helper), with fixed arguments and no shell:
   - `git_open(path)`: checks it's a repo; returns branch, upstream, ahead/behind, `origin` URL (to match it to the GitHub repo)
   - `git_status(path)`: `git status --porcelain=v2 --branch -z` → staged / unstaged / untracked / conflicted lists
   - `git_diff(path, file, staged)`: the diff for one file
   - `git_stage(path, files)` / `git_unstage(path, files)` / `git_discard(path, files)` (asks first in the UI)
   - `git_commit(path, message)`, `git_pull(path)` (`--ff-only`), `git_push(path)` (sets upstream if missing), `git_branches` / `git_switch(path, branch, create)`
   - Paths are checked: must be inside the opened repo, no `-` options, so the page can't make git do anything else.
2. **Folder picker:** `tauri-plugin-dialog` (Rust crate + `@tauri-apps/plugin-dialog`). The last folder per repo is remembered in `localStorage`.
3. **Let the live site call these commands:** the desktop window loads https://cocommit.vercel.app, so the capability file allows IPC from that site (and `localhost:3000` for dev) for **only** the commands above. This is a security trade-off: anything running on that site could run those git commands on the user's machine. Keep the list small, and never add a generic "run command".
4. **Browser side:** `src/lib/local-git.ts` wraps the commands (`isDesktop()`, `openRepo`, `status`, `stage`, …) with the same error style as `github-client`.
5. **Repo page:** a **GitHub | Local** switch, shown only in the desktop app.
   - Local mode: "Choose folder", then the branch with ↑ahead/↓behind.
   - Three lists: **Staged**, **Changes**, **Untracked**, each with stage/unstage buttons.
   - A diff view, a commit box, and **Pull** / **Push** buttons.
   - After a push, an "Open PR" button that reuses the existing GitHub mode.

## How we'll verify
- In `npm run tauri dev` on a test clone:
  - create, modify and delete files → they show under Untracked / Changes; stage some → they move to Staged
  - commit → `git log` shows it; push → it appears on GitHub; pull after a remote change → fast-forwards
- Path guard: a path outside the repo is refused.
- In a normal browser the Local switch isn't shown, and the website is unchanged.
