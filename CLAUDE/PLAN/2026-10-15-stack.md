# Plan: Tech stack for CoCommit

**Status:** active <!-- proposed | active | done | rejected | superseded -->
**Date:** 2026-10-15 · **Superseded by:** —

## Why
CoCommit needs beginner-friendly git (buttons, not terminal), chat, calls, file sharing and tasks. It must work on phone and desktop and be buildable quickly for a hackathon.

## Approach
1. **Client:** Next.js (TypeScript), responsive, installable as a PWA, so phones need no app store.
2. **Desktop:** Tauri 2 wraps the same UI in a native app (Windows/macOS/Linux) and can run real `git` on local folders.
3. **Git on phone/web:** GitHub OAuth + GitHub API (Octokit) for commits, branches and PRs.
4. **Chat, tasks, files, auth:** Supabase (Postgres, Auth, Realtime, Storage).
5. **Calls:** LiveKit (WebRTC), cloud free tier.
6. **UI / deploy:** Tailwind + shadcn/ui; web deployed on Vercel.

## Files touched
- Skeleton scaffolded by hand on 2026-10-15 (no installs yet): `package.json`, `src/`, `src-tauri/`, `public/`.

## Risks / needs OK
- Package installs and new service accounts (Supabase, LiveKit, Vercel, GitHub OAuth app) need the owner's OK.
- Tauri needs a Rust toolchain on desktop build machines.
- Local git through Tauri versus GitHub API on phone means two git code paths.

## How we'll verify
- Scaffolded app runs in a desktop browser, on a phone (PWA), and as a Tauri window; a test commit via the GitHub API succeeds.
