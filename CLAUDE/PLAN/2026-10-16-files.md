## Why
`/files` is a "coming soon" page (`src/app/files/page.tsx`). Teams share screenshots, PDFs and assets in Discord today; CoCommit should do it next to chat and git. Demo scope (`PLAN/2026-10-15-demo-scope.md`) listed file sharing as out of scope and code freeze is 09:30 on 2026-10-16, so this is **post-demo** work, unless Pattadon says otherwise.

## Approach
**Decided 2026-10-16 (Pattadon): store files in the team's GitHub repo under `COCOMMIT/files/`**, using the existing commit code. No new service, SQL or package. Supabase Storage was the other option and is not used.

1. `src/lib/files-util.ts` (pure): folder name, 3 MB limit (Vercel's 4.5 MB body limit, base64 adds a third), safe file names, unique names, size text.
2. `commitFiles` accepts `encoding: "base64"` per file (binary); the server makes a git blob and the tree points at it (`git-modes.ts` `treeEntries` takes the blob ids).
3. Two new GitHub actions: `listSharedFiles(repo)` (name, path, size from the default branch tree) and `downloadFile(repo, path)` (base64, only inside `COCOMMIT/files/`). Fake mode keeps files in the dev server's memory.
4. `src/lib/files.ts` (browser): `uploadSharedFile`, `deleteSharedFile`, `listShared`, `downloadShared` on top of `github-client`. Uploads and deletes post a git event to chat like any commit.
5. `/files` page: current repo, Choose file or drag-and-drop, list with size, Download and Delete, empty / signed-out / error states, phone width.
6. `tests/files.test.mjs`, LIB entry `files`, README and PROJECT.md lines.
