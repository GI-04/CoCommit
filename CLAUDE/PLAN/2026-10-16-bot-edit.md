# Plan: the Assistant edits files and opens a pull request (agentic edit mode)

**Status:** active <!-- proposed | active | done | rejected | superseded -->
**Date:** 2026-10-16 · **Superseded by:** —
**By:** Claude-proud (for proud) · approved by proud 2026-10-16 · builds on `PLAN/2026-10-16-bot-code-and-models.md` (merged in PRs #54 and #57)

## Why
proud wants the bot to help **change** files, like a cloud coding agent: "rename X", "fix the typo on the login page", "add a TODO item". Today it can only read.

## Approach

### 1. Two modes in the Assistant
- **Ask** (now): read-only, as today.
- **Edit** (new): a switch next to the input. Claude can read *and* stage changes. Edit only works in the Assistant, not in chat `@cocommit` (chat stays read-only).

### 2. Nothing is written until you approve
1. You ask, e.g. "change the landing page title to 'CoCommit — Git for beginners'".
2. Claude reads the code and stages changes with new tools (below). The staged changes live **only in that request**; nothing touches GitHub yet.
3. The answer shows a **change card**: what it did, each changed file with a line diff (+ green / − red), and the buttons **Create pull request** / **Discard**. You can also untick files.
4. **Create pull request** commits the ticked files in **one commit to a new branch** `assistant/<short-name>`, made from the branch you were reading, then opens a PR into it. It uses your own GitHub login (`commitFiles` + `openPullRequest`, which already exist). The card then links the PR.
5. **It never commits to `main` (or the picked branch) directly.** People review and merge the PR as usual; merging `main` still deploys.
6. To change the result, keep chatting ("also update the README"). The next answer stages on top of the previous changes, sent back with the request.

### 3. New tools (Edit mode only)
| Tool | Does |
|---|---|
| `edit_file(path, old_text, new_text)` | Replace one exact, unique piece of text (fails with a clear message if it's missing or appears more than once) |
| `write_file(path, content)` | Create a file, or replace a whole file |
| `delete_file(path)` | Delete a file |
| `show_changes()` | The staged changes so far, as a diff |
- `read_file` and `search_files` see the staged versions, so multi-step edits work.
- **Don't-read list applies to edits too:** excluded paths can't be edited.
- Text files only; binary files can't be edited. Max 200 KB per file, 30 files per change set.

### 4. Model, time and cost
- Edit mode works with any model choice; the hint says Balanced (Sonnet 5.5) or Best (Opus 5.5) edit more reliably than Fast.
- Edit requests may take longer: `maxDuration` 300 s for `/api/bot` (the GitHub route already uses 300), up to 20 tool rounds, and the forced final answer moves from 40 s to 240 s.
- The final answer must summarize what changed and anything left to do.

### 5. Not in this version ("cloud agent" parts that need a sandbox)
- **Running code, tests or builds.** There's no machine to run them on here. Claude only edits text, and the PR is where people check it. A later step could use Anthropic's Managed Agents (a hosted sandbox that clones the repo and runs commands), but that's a bigger change.
- Committing without a PR, editing binary files, and edits from chat.

## Risks / needs OK
- **Prompt injection:** a file, PR or issue could contain text that tells the bot to make a bad change. Two guards: you see the diff before any commit, and people review the PR before merging.
- **Writes use your GitHub login:** the PR shows up as yours. Someone with no write access gets GitHub's normal error.
- **Cost and time:** an edit on Opus can take a minute or more and cost more than reading.
- **Deadline:** the hackathon submission is due today. This is new code in the Assistant, so it's safer to merge after the demo, or behind the Edit switch (off by default) if it goes in before.
- No package installs. Commit/push/PR only when proud asks.

## How we'll verify
- `npm run typecheck`, `npm test`, `npm run build`.
- Offline route tests with a fake Claude and a fake GitHub (staging, diffs, the apply route's single commit and PR, refusals).
- Locally against **real GitHub** with the real Claude key, as for #54: ask for a small change (e.g. a typo in a `COCOMMIT/` note) → check the diff card → Create pull request → the PR appears on a new `assistant/...` branch with one commit → close it and delete the branch afterwards (ask proud first).
