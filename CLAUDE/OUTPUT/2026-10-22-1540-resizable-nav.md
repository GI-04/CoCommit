# Resizable sidebar (2026-10-22, Claude-Trin)

Plan: `PLAN/2026-10-22-resizable-nav.md` (done). Branch `trin/resizable-nav` (from `trin/liquid-glass`, so it includes PR #69's glass work). Not committed.

## What it does
- **Desktop (≥ 1024 px):** drag the sidebar's right edge (a line of light shows on hover) to set its width, **224–360 px**. The page content moves with it.
- Drag it under ~140 px and it **snaps to the icon rail** (80 px, the tablet look); drag out again to open it.
- **Double-click** the edge: back to the default 254 px.
- **Keyboard:** Tab to the edge (blue line), ← / → 16 px, Home = rail, End = widest, Enter = rail ↔ last width. Screen readers hear "Resize navigation, separator, 254 pixels" / "Icons only".
- **Saved per device** (localStorage `cocommitNavWidth`) and applied before the first paint, so no jump on reload.
- Tablet and phone: unchanged.

## How
- `src/lib/nav-width.ts`: limits, drag/arrow-key maths, read the saved value, `applyNavWidth`, `NAV_WIDTH_SCRIPT` (the head script).
- `--nav-w` on `<html>` (default in `:root`), `data-nav="rail"` for the rail. New Tailwind variant `full:` (desktop and not rail) replaces `lg:` in `Nav.tsx` and `UserChip.tsx`; `<main>` padding is `--nav-w` + the old gap.
- While dragging: no sidebar transitions, resize cursor everywhere, no text selection, plain blur instead of the light-bending lens (refits after).
- The minimum was 200 in the plan; at 200 "Agent Context" wrapped to two lines (needs 219 px), so it's 224 and labels are `whitespace-nowrap`.
