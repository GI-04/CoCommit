# Figma look in the app (theme, navigation, Home, polish pass)

**Added:** 2026-10-16 · **Kind:** reference

## Takeaway
The app follows the Figma file "CO-Commit" (page "test 4", key `A5ao1epDSl3hnbGX599un3`): dark only, chunky colour blocks with black outlines, paper-white rows, glass navigation. It is done by changing the colour tokens, not by rewriting pages (`PLAN/2026-10-16-figma-ui.md`, phases 1 and 2).

## Details
- **Tokens (`src/app/globals.css`):** canvas `#1f1f1f`, accent blue `#1f4ae0` (text uses `accent-soft` `#8fa9fa`), `pink #ff79bf`, `cyan #00a9d8`, `mustard #d8a500`, `green #68ca27`, `clay #e07a5f`, paper `#fffdf8`. Pages keep using `bg-bg / bg-surface / text-fg / text-muted / border-line / bg-accent`.
- **Cards flip the tokens:** `.bg-surface` and `.block-pink|cyan|mustard|green|clay|paper` set dark-on-light values for `--foreground`, `--muted`, `--border` (black), `--background` (paper, so inputs are paper), `--accent` (black primary button). So content inside a card needs no extra classes. Use `<Card tone="pink">` (or `"dark"` for the dark diff panel). Use `hover:bg-fg/10`, never `hover:bg-line/..` (the line colour is black inside cards).
- **Glass:** `.glass` (sidebar, rail, top bar, tab track, pills), `.glass-thumb` (active item) and `.btn-glass` (glass buttons). Since 2026-10-22 a fuller liquid glass with light bending, pointer light and spring motion: see "Liquid glass 2" below.
- **Navigation (`src/components/Nav.tsx`):** one element, three sizes: ≥1024 px sidebar with labels, ≥768 px icon rail, below that a top bar with a menu button. Items come from `src/lib/sections.ts` (`title`, `icon`). Hidden on `/` (landing) and `/login*` (see `AppShell.tsx`). Icons are inline SVG in `icons.tsx`; the logo is `public/logo-mark.svg` (exported from Figma, shown with the `invert` class).
- **Shared UI (`ui.tsx`):** `PageHeader`, `Card tone`, `Button` (`primary`, `ghost`, `glass`, `blue`), `Tabs` (buttons only; keep this file free of `next/link` because `tests/profile.test.mjs` loads it with a minimal import list), `Pill`. `Avatar` colours come from the name. Auth screens use `AuthShell.tsx` (`authField`, `authButtons`).
- **Home (`src/app/home/page.tsx`, `src/components/home/`):** tabs Cards / Overview / Activity (last tab remembered in `localStorage` `cocommitHomeTab`). Data hooks in `home/data.ts` give each card the same states (`loading | ready | login | no-workspace | error`) so a card says what is wrong instead of showing made-up numbers. **Customize** (hide, move with arrows) is pure logic in `src/lib/home.ts` (`resolveLayout`, `moveCard`, `toggleCard`, `timeAgo`), stored per device (`cocommitHomeCards`). Cards: a link card per screen, Work done and Team board (from `loadBoard`), Overview stats + heat map + team (COLLAB.md), Activity (`recentActivity`, newest first) + Today + Streak.
- **Not built (no data source, so not mocked):** open-PR count, Calendar, Quick access, Sticky note, Work-done bar chart, Assistant window, per-person conversations.
- **Tests:** `tests/home.test.mjs` (layout, timeAgo), `tests/heatmap.test.mjs` (streak, commits per day), `tests/diff.test.mjs` (diff rows with line numbers). The visuals were checked in the browser at 390 / 834 / 1440 px on demo data only; real GitHub data was not checked.

## Polish pass (2026-10-16, `PLAN/2026-10-16-figma-ui-polish.md`)
- **Navigation = Figma's:** `navItems` in `src/lib/sections.ts`: Home, Repository, Drive (`/files`), Messages (`/chat`, active also on `/tasks` and `/calls`), Agent Context, plus the **Assistant** button (not a page). `sections` is still used by other code (labels).
- **Messages:** `MessagesShell` (title + `LinkTabs` Chat / Team / Call) wraps `/chat`, `/tasks`, `/calls`. `ListPanel` is the left list (on narrow screens it becomes a pill row): chats = `# general` + the person's repos (`useRepos()`, each repo is a live chat); teams = the person's repos (switching sets the repo for tasks, chat, calls). Team also has Invite (GitHub's access page) and Members (COLLAB.md). Grids use `minmax(0,1fr)` on phones, otherwise long URLs widen the page.
- **Assistant (`src/components/Assistant.tsx`):** a window opened only from the **Assistant** item in the navigation (no floating button; provider in `AppShell`), built on `askBot` (`POST /api/bot`): answers from `COCOMMIT/` with sources; conversation is kept while you move between pages; needs `ANTHROPIC_API_KEY` on the server, otherwise the window shows "isn't set up". `useAssistant()` lets other screens open it (Context's "Ask assistant").
- **Repository:** left card with Changes / Files tabs, pink Commit card (message, new branch, Commit, PR title + Open PR, Discard edits), right dark panel with Diff / Edit. `DiffView` + `src/lib/diff.ts` (`parsePatch`, tested) number lines and also serve Local folder mode. Same API calls as before.
- **Drive (`/files`):** coloured file cards (grid) or list, Upload button, dashed upload card, drag and drop on the whole area. Personal / Shared tabs are not built (one shared folder).
- **Profile:** Overview (`components/profile/Overview.tsx`: profile card, commits by you, your repos as teams, recent activity) and Account (details form, connected accounts, email and password). Sign out is in the header. `tests/profile.test.mjs` renders the Account tab and stubs the Overview.
- **Context:** tabs Instructions, Handoff, Team, Decisions, Gotchas, Log, To-do, Board read the real `COCOMMIT/` files through `loadWorkspace` (`useWorkspace`), read-only with "Open on GitHub" links; no longer demo text. A **Set up team context** form (`components/SetupForm.tsx`, calls `setUpWorkspace`) appears when the repo has no `COCOMMIT/`; editing the files is still on GitHub (`saveHandoff`… helpers exist).
- **Landing (`src/app/page.tsx`):** Figma sections (glass header, "Git, with buttons.", colour cards, steps, "Get CoCommit.") with the interactive `HeroDemo`, the "Why" diff and the FAQ kept; the old git-graph rail (`components/landing/Rail.tsx`) is no longer used and the stale "Coming next" section is gone. Logos: `public/logo.svg` (wordmark) and `public/logo-mark.svg`, shown with `invert`.
- **Dev note:** after adding an icon, restart `npm run dev`; hot reload can keep an old `icons.tsx` on the server (empty icon, hydration error).

## Motion and fidelity (2026-10-16, `PLAN/2026-10-16-figma-fidelity-motion.md`)
- **Motion is CSS only** (`globals.css`): `.rise` (fade up, `--d` delay for stagger), `.pop`, `.grow` (bars), `.lift` (hover lift on link cards), `.shimmer` (loading), `.reveal` (landing sections, scroll timeline where supported), button press (`:active` scale), sliding glass thumb in `Tabs` (pure CSS: equal-width tabs, `translateX`), page enter in `AppShell` (`key={path}`). `prefers-reduced-motion` turns it all off. Use `fill-mode: backwards`, never `both`, on anything that also has a hover transform.
- **Sizes taken from the Figma frames (1440 px):** content top 57, header row 75, tab thumb 59 / tab 177, nav item 62 at a 70 pitch, logo 40 high at y=72, auth card 790 wide, Drive cards 410 high, Repository list 298 wide.
- **Testing animations:** the browser test pane freezes CSS animations; call `document.getAnimations().forEach(a => a.finish())` before measuring or taking a screenshot.

## UX round 2 (2026-10-16, `PLAN/2026-10-16-ux-round-2.md`)
- `src/lib/errors.ts` `friendlyError` turns GitHub and network errors into plain sentences (used by Repository, Drive, Tasks, Home data, setup form); our own messages pass through. `ui.tsx` has `Skeleton` (loading placeholder) and `Tabs` is keyboard-friendly (arrows, Home/End, one tab stop). `components/home/Trouble.tsx` says why a card is empty with a Log in / Set up team context link. Route `layout.tsx` files give each page its tab title ("Repository · CoCommit"); `not-found.tsx` and `error.tsx` are the 404 and crash pages.
- Audit tip: in the browser, check unlabelled controls, tap targets under 36 px, text under 11.5 px and horizontal overflow at 390 px; it found the chat input label, 10 px labels and the shared tab title.

## Glass buttons, tab slide, team spines, Home summaries (2026-10-16, `PLAN/2026-10-16-glass-buttons-spines.md`)
- **Buttons:** `buttonClass(variant, className)` in `ui.tsx` (also for links such as Invite) makes every button a pill: `glass` = secondary (`.btn-glass`), `blue` = main action (`.btn-blue`), `primary` solid, `ghost` outlined. `tests/ui.test.mjs` renders `Button` and fails on a second radius class. Gotcha: Tailwind 4 sorts same-property utilities by value, so a `py-1` or `rounded-md` in the same class string loses or wins by size, not by order (use `!py-1` or a `size` prop).
- **Tab slide:** `Tabs` (in-page, pure CSS) takes `variant="paper"` (white track, black thumb: Repository Changes/Files, email Log in/Sign up) and `size="sm"`. `LinkTabs` (Messages Chat/Team/Call, separate pages) keeps the last thumb place in a module variable and slides from it; it forgets it after 2 s. Drive's grid/list switch has its own thumb. Testing: `th.getAnimations()` shows a running `CSSTransition` on `transform` after the click; `getAnimations().forEach(a => a.finish())` then reads the end place.
- **Team spines:** `src/lib/team.ts` (`groupTeam`, `agentLabel`; agents are `<Agent>-<Owner>` titles filed under the owner by title or name, one colour per person) and `src/components/TeamSpines.tsx` (tap a bar to open Role / Can do / Available / May write). Used on Agent Context → Team and Messages → Team → Members. Demo mode serves a small demo `COCOMMIT/COLLAB.md` (`fake.collab` in `github.ts`) so these views have people.
- **Home summaries:** `src/lib/home-summary.ts` (pure) and the four hooks in `components/home/data.ts` (`useLatestCommit`, `useRecentChat`, `useNextStep` = first line under a "next step" heading in HANDOFF.md, `useDriveFiles` = first three files). A card whose data can't load keeps its blurb. Cards sit in a `grid-cols-[minmax(0,1fr)]` grid with `min-w-0` items: without that, a long `truncate` line widens the whole page on phones.

## Home drag and drop (2026-10-16, `PLAN/2026-10-16-home-drag-drop.md`)
- In Home → Customize a card can be dragged onto another: it takes that place on drop (`moveCardTo`), saved per device like the arrows. `src/components/home/useCardDrag.ts` (pointer events, window listeners, no pointer capture): a mouse grabs anywhere except buttons; a finger or pen only by the grip (`data-drag-handle`, `touch-none`). Escape, a lost release, blur or leaving Customize puts the card back. Pure helpers in `src/lib/home.ts`: `moveCardTo`, `cardAt` (drop target, with slop for the gaps), `autoScrollStep` (never past the scroll limit measured at the start: a lifted card adds scrollable area).
- Testing: the browser pane's real mouse drag (`left_click_drag`) works; for edge cases dispatch `PointerEvent`s on the card and on `window` (`pointerType` mouse / touch / pen, `buttons`). The pane doesn't run animation frames, so auto-scroll can't be seen there. Home remembers its last tab (`cocommitHomeTab`): the Customize button only exists on Cards.

## Liquid glass 2 (2026-10-22, `PLAN/2026-10-22-liquid-glass.md`)
- **Material (every browser, `globals.css`):** one shared background for `.glass, .glass-thumb, .btn-glass` built from per-class knobs (`--top --bottom` sheen, `--pool` light at the bottom edge, `--edge` rim, `--glow` pointer light, `--tint`). Bars and pills have `--tint: 0.75` of the canvas colour (#1e1e1e): invisible on the canvas, but white text on glass over a white card goes from unreadable to about 4.7:1 (landing header, phone top bar). `saturate(160%)` in the backdrop. `prefers-reduced-transparency` → solid #2c2c2c, no backdrop filter.
- **Pointer light:** `GlassEffects.tsx` (mounted once in `AppShell`) writes `--lx/--ly` (% of the box) on the glass under the pointer, its glass ancestors and their thumbs, at most once a frame. CSS shows the highlight while `--lit` is 1 (`:hover` on pointer devices, `:active` on touch, thumbs of a hovered bar). `--lx --ly --lit` are `@property`-registered with `inherits: false` (a thumb must not inherit its track's light) and `--lit` transitions.
- **Light bending (Chromium only):** `useLightBending` gives every `.glass` / `.btn-glass` an SVG filter as `--lens` (`backdrop-filter: var(--lens, blur(20px)) saturate(160%)` under `:root[data-refract]`). The filter: the frosted backdrop (`feGaussianBlur`, `edgeMode=duplicate`, deviation 12) with the backdrop bent by `feDisplacementMap` shown on top only along the rim (map's blue channel → alpha). Maps come from `src/lib/glass-map.ts` (`lensFit`, `lensMap`: rounded-rect distance, bend `1 − √(1 − t²)`, samples inward so they stay inside the element; tested in `tests/glass.test.mjs`). One filter per size+radius, shared; ResizeObserver refits after 120 ms; a MutationObserver picks up glass that appears later. Detection: `navigator.userAgentData` brand "Chromium" + `CSS.supports`; Safari, Firefox and the macOS desktop app (WKWebView) keep the CSS glass. Over the flat canvas the bend is invisible by design (Trin kept the flat Figma canvas): it shows where content passes under glass.
- **Motion:** `--spring` (8 % overshoot) and `--spring-bouncy` (12 %) are damped springs sampled into `linear()`, falling back to `--ease-out`. Sliding thumbs are an outer `.slide-thumb` (spring on transform/size) and an inner glass re-keyed on every move (`stretch-x` / `stretch-y`: stretches toward the move, wobbles, settles). The stretch only plays after a user move: the group gets `data-slide="next" | "back"` (transform origin = leading edge). Tab tracks wrap the thumb in `.slide-clip` (`overflow: clip`) so an overshoot past the first/last tab squishes against the end and never makes the scrollable track show a scrollbar. `Tabs` stays hook-free (sets `data-slide` on the tab list in its click/key handler). The sidebar is now one sliding thumb (`useSlidingThumb` in `Nav.tsx`, measured in a layout effect; until measured, the active link wears `glass-thumb` itself). Glass and blue buttons press with a quick-in (`:active` transition) / springy-out (normal transition) squish.
- **Testing:** the browser pane runs hidden pages without animation frames, so test scripts use `setTimeout`, not `requestAnimationFrame`; pause animations and set `currentTime` to measure mid-move (`getBoundingClientRect` of the inner thumb), screenshots don't show paused frames. To see the bend, put a striped `position: fixed` div under the glass. Landing page has infinite animations: wrap `a.finish()` in `try`.
