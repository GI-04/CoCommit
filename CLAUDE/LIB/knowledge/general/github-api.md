# GitHub sign-in and git API (`src/lib/github.ts`)

**Added:** 2026-10-15 · **Kind:** reference

## Takeaway
Server code imports `@/lib/github`; `"use client"` screens import `@/lib/github-client`. Both have the same function names, and the client calls them through `POST /api/github/<name>`. While `GITHUB_CLIENT_ID` is empty, everything returns fake data. To test the real code path without a real token, run the dev server against `sources/general/mock-github.mjs`.

## Details
- **Current integration (2026-10-15 inspection):** Repo UI calls this API. `github-types.ts` imports only the `Activity` type from pure `context.ts`; it has no server dependency. Built-in fake mode persists only the legacy `COCOMMIT.md`, not arbitrary workspace files; use the stateful mock for workspace tests.
- **Types:** shared shapes and the `GitHubActions` list live in `src/lib/github-types.ts` (type-only import from pure `context.ts`). Browser code imports types from there, never from `github.ts` (server code; importing it, even as a type, made `next dev` reload open tabs forever).
- **Functions** (repo = `"owner/name"`): `getSession` (`{ user, fake }`, user null = not signed in), `listRepos`, `listBranches` (string[]), `getChanges(repo, branch)` (branch vs default branch = what its PR contains; statuses `added | modified | deleted`), `commitFiles(repo, branch, [{ path, content | null }], message)` (one commit; null deletes; creates the branch from default if missing), `openPullRequest(repo, head, base, title, body?)` (returns the already-open PR instead of failing), `readFile(repo, branch | null, path)` (null if missing), `listFiles`, `readContext` / `writeContext` (`COCOMMIT.md` on default branch), `listCommits(repo, limit = 10)` (default branch, newest first) and `listMergedPulls(repo, limit = 10)` (merged PRs only), both as `Activity` items from `context.ts` for `COCOMMIT/LOG.md` (`addActivity`). `listCommitDates(repo, since)` returns `{ author, at }[]` since an ISO date (up to 500) for the heat map (LIB `heat-map`). Fake mode includes fake commits made on `main`. In `github-client`, `commitFilesQuietly` commits without posting a chat git event (for automatic log updates).
- **File modes on commit (`src/lib/git-modes.ts`):** `commitFiles` reads `git/trees/<base>?recursive=1` and keeps each existing file's mode (`100755` stays executable, deletions use the file's own mode, new files `100644`); symlinks (`120000`) and submodules (`160000`) are refused with a 400; a truncated listing falls back to `100644` for unlisted paths. Tests: `tests/git-modes.test.mjs`.
- **Errors:** server throws `GitHubError` (`.status`); client throws `GitHubRequestError` (`.status`). 401 = not signed in → send the browser to `signInHref()`.
- **Sign-in (login identity, `kin/login-identity`):** `GET /api/github/login?returnTo=/path`. If Supabase's GitHub provider is on (checked live via `/auth/v1/settings`), it goes through Supabase (`signInWithOAuth`, scopes `repo read:user`) → GitHub → Supabase → `/auth/callback?next=…&provider=github`, which keeps GitHub's `provider_token` sealed in `cc_github` (`saveGitHubToken`, only for real GitHub identities; helpers in `src/lib/login-identity.ts`). Otherwise the legacy own OAuth: → GitHub → `GET /api/github/callback`. `getSession` adds `needsReconnect: true` for a Supabase GitHub user without a usable token. `POST /api/github/logout` and `POST /auth/signout` clear **both** the token and the Supabase session. Token lives in cookie `cc_github`, AES-256-GCM-encrypted with a key from `GITHUB_CLIENT_SECRET`, `httpOnly`. Scope `repo read:user`. **Return paths (2026-10-19, `PLAN/2026-10-19-security-fixes.md`):** every `returnTo` / `next` goes through the one `safeReturnTo` in `src/lib/login-identity.ts` (login page, `auth-email.ts`, `/auth/callback`, the legacy callback in `github.ts`); it refuses `//`, any `\` and control characters, since browsers turn `/\x` and `/<tab>/x` into another site. After a sign-in that brings no GitHub token (Google, email links, a desktop ticket without one), `cc_github` is deleted unless the account has its own GitHub identity.
- **Repo access as a user (`canSeeRepoAs(user, repo)`, server only, not in `actions`):** like `canSeeRepo`, but when a Supabase user is signed in, the GitHub account behind `cc_github` (GitHub `/user` id) must be that user's own linked GitHub identity (`githubIdOf` / `sameGitHubAccount` in `login-identity.ts`); otherwise `"no-github"`. `/api/chat/join` and `/api/livekit-token` use it, so a GitHub cookie someone else left on the browser can't make an account a repo member.
- **Env:** `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`; optional `GITHUB_API_URL`, `GITHUB_WEB_URL` (GitHub Enterprise or the mock).
- **No packages:** plain `fetch`, no Octokit.
- **Mock test:** start `node <path>/mock-github.mjs` (port 4010), then run the dev server with the env pointed at it. zsh: `GITHUB_CLIENT_ID=test-id GITHUB_CLIENT_SECRET=test-secret GITHUB_API_URL=http://127.0.0.1:4010 GITHUB_WEB_URL=http://127.0.0.1:4010 npx next dev -p 3100`. PowerShell 7: set each with `$env:NAME="value"` first, then `npx next dev -p 3100`. Sign in by following `/api/github/login`'s redirect `state` into `/api/github/callback?code=good-code&state=<state>`. The mock serves repo `acme/app` (branches `main`, `feature/x`); `GET /__log` shows every request it got.
