# Chat backend (`src/lib/chat.ts`)

**Added:** 2026-10-15 · **Kind:** reference

## Takeaway
`"use client"` screens import `@/lib/chat`. Chat is one Supabase Realtime channel per repo ("owner/name"). Without the Supabase keys it runs in fake mode (this browser only: `localStorage` plus `BroadcastChannel`, so two tabs can chat). The table, rules and Realtime setup are in `supabase/schema.sql`, which Pattadon runs once after `profiles.sql`.

## Details
- **Members only (2026-10-16, PLAN/2026-10-16-chat-privacy-get-started.md):** chat no longer signs visitors in anonymously. Signed out (or with an old anonymous session), `loadMessages`, `listPinned` and `pinMessage` throw `NotSignedInError` (message `LOGIN_TO_CHAT`), and `subscribe` / `onlineUsers` don't join; `/chat` shows a "Log in to see and join the team chat" card instead of the list and composer. The table rules (`schema.sql`, `profiles.sql`, and on the live project the RESTRICTIVE "real accounts only" policies from `supabase/chat-privacy.sql`, live since 2026-10-16 09:33) refuse anonymous sessions for reading, pinning and profiles, because anonymous users count as `authenticated` and the anon key is public. Check from outside with `node scripts/check-chat-privacy.mjs` (must print 0 and 0). Still open: per-repo membership and public presence channels (TODO).
- **Identity boundary (2026-10-15 inspection):** RLS binds `author_id` to the Supabase user, but the browser supplies the displayed `author` name. It does not prove GitHub identity or restrict reads/pins by repo membership. `/chat` still uses `GI-04/CoCommit` from `mock.ts`, independently of the Repo picker.
- **Who's talking (login identity, PR #24, PLAN/2026-10-15-login-identity.md):** only real accounts (GitHub through Supabase, email or Google) can **read or post** (see "Members only" above): `canPost()` checks first, and the select, insert and pin policies in `schema.sql` reject anonymous users. The database sets `author` (profile name, else GitHub login) and `author_login` (verified GitHub login from `profiles.github_login`) in `chat-author.sql`, whatever the browser sends; the page shows `@login ✓`. "Change name" now links to `/profile` (`setMyName` and the `cocommit-chat-my-name` key are gone). `myName()` is only for presence/the "You:" line. Messages load with `select("*")` so chat works before `author_login` exists.
- **Which chat (PLAN/2026-10-16-demo-polish-kin.md):** `/chat` has two tabs: **#general** (`messages.repo = 'general'`, the whole team) and **# owner/name**, the repo last picked on `/repo` (`src/lib/current-repo.ts`, `localStorage` key `cocommit-current-repo`, only saved from a real repo list; default `GI-04/CoCommit`). Switching clears the list and reloads; a late answer for the old chat is ignored; the online list follows the open chat. Decision/Gotcha are hidden on #general (they save into a repo's `COCOMMIT/`); the `@cocommit` bot uses the picked repo from either tab. `CallChat.tsx` keeps its own repo.
- **Don't import `github.ts` from browser code, even for types:** it made `next dev` reload two open tabs forever. Use `github-types.ts`.
- **Functions:** `loadMessages(repo, limit?)` (oldest first), `sendMessage(repo, text)`, `postGitEvent(repo, summary)`, `pinMessage(id, pinned?)`, `listPinned(repo, limit?)` (pinned messages, newest first, as `Activity` items for `COCOMMIT/LOG.md`), `subscribe(repo, onMessage)` and `onlineUsers(repo, onChange)` (both return a stop function), `myName()`, `canPost()` (real account, or fake mode), `NotSignedInError`, `LOGIN_TO_CHAT`, `mergeMessage(list, m)` (add or replace by id, keeps order), `chatFake`.
- **Pin as decision / gotcha** (`src/lib/chat-pins.ts`): `saveAsDecision(repo, message, fields)` / `saveAsGotcha(...)` check that `COCOMMIT/CONTEXT.md` exists (else `NoWorkspaceError`), add the entry through `addDecisionTo` / `addGotchaTo` (`workspace.ts`), then pin the message. `decisionFields(m)` / `gotchaFields(m)` prefill the form. Needs GitHub login (it's a commit): 401 → show `signInHref("/chat")`.
- **Shape:** `ChatMessage = { id, repo, author, text, kind: "text" | "git_event", pinned, createdAt }`, the same as `mock.ts`.
- **Your own messages come back through `subscribe` too.** Always add with `mergeMessage`, so nothing shows twice.
- **Git events:** `github-client.ts` posts one after every `commitFiles`, `openPullRequest` and `writeContext`. The text ends with " · <GitHub URL>" of the commit or PR. If posting fails, it's ignored.
- **Rules (RLS):** real accounts (not anonymous sessions) read everything and post only as themselves (`author_id` defaults to `auth.uid()`); `update` is granted on the `pinned` column only. `author` is the display name, stored at insert so Realtime payloads need no join. `supabase/chat-author.sql` (trigger): a poster with a profile name always posts under it; a guest using a member's name gets " (guest)". Tested on local Postgres with a stand-in auth schema (`pg-test` recipe in PLAN/2026-10-15-backend-polish.md).
- **Fake mode:** storage key `cocommit-chat-messages` (last 500); channels `cocommit-chat:<repo>` and `cocommit-online:<repo>`. Each tab gets its own guest name (`sessionStorage`). Clear the history with `localStorage.removeItem("cocommit-chat-messages")`.

- **Repo members only (2026-10-16, Claude-Kin, branch `kin/repo-members-only`, `PLAN/2026-10-16-repo-members-only.md`):** before reading, posting or listening in a repo chat, `chat.ts` asks `POST /api/chat/join`, which checks GitHub (`canSeeRepo` in `github.ts`, rules in `repo-access.ts`) and records the user in `repo_members` with the service role key (`supabase-admin.ts`, env `SUPABASE_SERVICE_ROLE_KEY`). `supabase/repo-members.sql` adds restrictive rules: a repo chat needs a membership checked in the last 24 h; `# general` (`repo = 'general'`) stays open to every real account. Not a member → `NotMemberError`, and `/chat` shows a card with **Open # general**. Email/Google accounts (no GitHub token) get `# general` only. Presence (who's online) isn't covered by the table rules. Order for going live: merge → key in Vercel → run the SQL.
